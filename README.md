# Russian Science Foundation Grant

**Инструменты для исследования идеологических направлений и экономических нарративов в русскоязычных текстах.**

Репозиторий объединяет исследовательские скрипты для обработки текстовых корпусов, в том числе стенограмм Государственной думы: построения эмбеддингов, классификации документов, извлечения нарративных триад и поиска их смыслового сходства с эталонами.

Для векторизации используется `mlsa-iai-msu-lab/sci-rus-tiny`, для классификации — модели LSTM / BiLSTM на TensorFlow и Keras, для синтаксического анализа и извлечения нарративов — Natasha. Результаты сохраняются в CSV, Excel и интерактивные HTML-графы.

> Проект опубликован как набор исследовательских скриптов. Для воспроизведения экспериментов необходимо подготовить собственные данные, настроить пути и согласовать окружение. Датасеты, обученные LSTM-модели и файл зависимостей в репозитории отсутствуют.

## Возможности

- Подготовка датасетов из текстовых файлов и назначение меток по названиям каталогов.
- Аугментация текстов путём объединения частей двух документов одного класса.
- Векторизация документов с помощью SciRusTiny.
- Классификация по пяти идеологическим направлениям и отдельные эксперименты с бинарной LSTM.
- Оценка моделей: accuracy, precision, recall, F1, отчёты классификации и матрицы ошибок.
- Стратифицированная кросс-валидация многоклассовой модели на десяти фолдах.
- Извлечение триад **«актор — действие — объект»**, спикера, даты и контекста предложения.
- Сопоставление нарративов с эталонными формулировками по косинусному сходству.
- Ранжирование найденных нарративов, сводки по годам и графовая визуализация.

## Основные направления обработки

```text
Русскоязычные документы (.txt)
│
├── Классификация документов
│   ├── Разметка по каталогам и аугментация
│   ├── Эмбеддинги SciRusTiny
│   ├── CSV: file, embedding, class
│   ├── Обучение и оценка LSTM / BiLSTM
│   └── Распределение документов по предсказанным классам
│
└── Анализ нарративов
    ├── Морфологический и синтаксический разбор Natasha
    ├── Триады: актор → действие → объект
    ├── Excel с триадами и контекстом
    ├── Сходство с эталонами SciRusTiny
    └── Ранжированные таблицы и HTML-графы
```

Эти направления можно использовать отдельно; репозиторий не содержит единого скрипта, автоматически запускающего весь процесс.

## Идеологические классы

| Индекс | Класс |
| --- | --- |
| `0` | Неолиберализм |
| `1` | Социализм |
| `2` | Дирижизм |
| `3` | Особый путь |
| `4` | Экологизм |

В `find_class()` класс определяется по вхождению названия направления в путь к файлу. Если ни одно из четырёх явно проверяемых названий не найдено, назначается `0`. Поэтому перед подготовкой датасета важно проверить структуру каталогов.

В скрипте `дву-LSTM предсказания.py` документ получает название предсказанного класса при максимальной оценке softmax **не ниже 50%**. Иначе результат обозначается как **«Неопределено»**.

## Подготовка окружения

### 1. Получение исходников

```bash
git clone https://github.com/MarkSkryabin/Russian-Science-Foundation-Grant.git
cd Russian-Science-Foundation-Grant
python -m venv .venv
```

Активация в Windows PowerShell:

```powershell
.\.venv\Scripts\Activate.ps1
```

Активация в Linux / macOS:

```bash
source .venv/bin/activate
```

### 2. Установка библиотек

Версии Python и библиотек в репозитории не закреплены. Ниже приведён список зависимостей по импортам исходников, а не проверенный lock-файл:

```bash
python -m pip install --upgrade pip
python -m pip install numpy pandas openpyxl tqdm scikit-learn matplotlib seaborn
python -m pip install torch transformers sentence-transformers natasha
python -m pip install tensorflow keras scikeras networkx pyvis requests urllib3
```

Код одновременно использует `keras`, `tensorflow.keras` и внутренние импорты `keras.src`. Подберите совместимые версии TensorFlow и Keras и при необходимости адаптируйте экспериментальные блоки к выбранному окружению.

В функциях эмбеддингов вызывается `model.cuda()`. В текущем виде для них нужны CUDA-совместимая видеокарта и соответствующая сборка PyTorch. Для CPU необходимо заменить этот вызов и согласовать устройство модели и входных тензоров.

Первое обращение к `from_pretrained()` требует доступа к Hugging Face для загрузки токенизатора и весов SciRusTiny.

### 3. Настройка проекта

Перед запуском выбранного этапа:

- Замените абсолютные пути `E:\Грант\…`, `E:\PycharmProjects\PARsing\…` и `E:\Downloads\…` на свои.
- Проверьте вставки `sys.path.append(...)`: они ссылаются на локальное окружение автора.
- Подготовьте входные данные и создайте выходные каталоги, если скрипт не создаёт их самостоятельно.
- В скриптах LSTM есть импорт `from SciRusTiny import get_embedding`, но модуля `SciRusTiny.py` в репозитории нет. Предоставьте этот модуль либо удалите неиспользуемый импорт после проверки выбранного блока.
- Проверьте обращения к `.h5`: необходимые сохранённые модели не входят в репозиторий. В некоторых скриптах загружается `model1`, хотя дальше обучается другая модель; такие загрузки нужно согласовать со своим экспериментом.

Многие файлы организованы секциями `##` и содержат несколько самостоятельных экспериментов, выполняемых последовательно при обычном запуске Python.

## Данные и форматы

### Исходные документы

Загрузчики читают текстовые файлы в кодировке **Windows-1251 (`cp1251`)**. Для подготовки обучающей выборки удобно организовать корпус так:

```text
corpus/
├── Неолиберализм/
├── Социализм/
├── Дирижизм/
├── Особый путь/
└── Экологизм/
```

Для аугментации нужно как минимум два подходящих документа в каждом используемом классе: второй документ выбирается случайно из того же направления.

При извлечении нарративов дата ищется в пути к документу в формате вроде `15 марта 2024`. Если такого фрагмента нет, текущий код потребует адаптации. Поиск спикера также учитывает структуру стенограмм и имена файлов с маркером `Часть`.

### Датасет эмбеддингов

Скрипт `создание датасета 2.0.py` сохраняет CSV с колонками:

| Колонка | Содержимое |
| --- | --- |
| `file` | Путь к исходному документу или обозначение аугментированного примера |
| `embedding` | Текстовое представление числового вектора |
| `class` | Индекс идеологического класса |

Длинный текст разбивается на фрагменты по символам; для каждого вычисляется нормализованный эмбеддинг, затем векторы усредняются. В экспериментальных моделях встречается фиксированная размерность `312`; при смене модели эмбеддингов размеры входов нужно проверить.

### Таблица нарративов

Текущая функция `writer()` формирует Excel со столбцами:

| Колонка | Содержимое |
| --- | --- |
| `speakers` | Определённый спикер |
| `actors` | Участники действия |
| `actions` | Действия |
| `objects` | Объекты действий |
| `sentence` | Исходное предложение |
| `path` | Путь к документу |
| `date` | Дата, извлечённая из пути |
| `connected sentences` | Окружающий контекст |

При расчёте сходства добавляются столбцы `sim_1`, `sim_2`, … по числу эталонных нарративов.

## Порядок работы

Команды ниже выполняются **после настройки путей, данных и зависимостей** для соответствующего этапа.

### Подготовка и классификация документов

1. Разместите размеченные `.txt` в каталогах идеологических направлений.
2. Настройте `path_name`, корневой каталог и путь сохранения CSV в скрипте подготовки датасета.
3. Выполните векторизацию и аугментацию:

   ```bash
   python "создание датасета 2.0.py"
   ```

4. Настройте путь к CSV, загрузки `.h5` и выбранный блок модели. Запустите обучение:

   ```bash
   python bidirectional-LSTM.py
   ```

5. Для отдельной оценки по десяти фолдам используйте:

   ```bash
   python "Кросс-валидация.py"
   ```

6. Для применения сохранённой модели к датасету эмбеддингов настройте входной CSV, `.h5` и правило формирования выходного пути:

   ```bash
   python "дву-LSTM предсказания.py"
   ```

Последний скрипт копирует документы в каталоги по предсказанным классам и создаёт CSV с полями `file`, `class_index`, `class_name`, `certitude`. Правило назначения выходного каталога использует замену фрагмента `Экономические стенограммы` в исходном пути и должно соответствовать вашему корпусу.

### Извлечение и сопоставление нарративов

1. В `narrative_funcs_actually.py` настройте `path_to_files`, `path_to_all_files` и `output_dir`.
2. Запустите извлечение триад и сохранение Excel:

   ```bash
   python narrative_funcs_actually.py
   ```

3. В `similarity_funcs.py` проверьте список, возвращаемый `get_example_narratives()`. В текущем варианте используются 12 эталонных формулировок.
4. Настройте входные и выходные пути в `similarity_count.py`, затем рассчитайте сходство:

   ```bash
   python similarity_count.py
   ```

5. Настройте каталоги и порог `threshold` в `similarity_ranging.py`:

   ```bash
   python similarity_ranging.py
   ```

По умолчанию отбираются строки со сходством **строго выше `0.8`**. Для каждого эталона формируется отдельная таблица, отсортированная по убыванию соответствующего `sim_*`.

## Особенности текущей реализации

- Анализ тональности и модальности по умолчанию отключён через `predict=False`. В основном запуске модель тональности не инициализируется, а текущий `writer()` не экспортирует эти поля. Для их использования нужно согласованно изменить вызовы, инициализацию и схему вывода.
- `graphs_vis.py` содержит блоки, ожидающие дополнительные колонки, например `PER` и `tonality`, которых нет в стандартном выводе `writer()`. Выбирайте подходящий блок или адаптируйте таблицу.
- Аугментация выполняется до разбиения датасета. Для независимой оценки модели следует разделять исходные документы до аугментации и исключать попадание связанных примеров в разные выборки.
- Вектор документа подаётся в ряде LSTM-экспериментов как один временной шаг `(1, embedding_dim)`. Это важно учитывать при интерпретации архитектуры.
- Число процессов задано в коде: 10 для извлечения нарративов и 8 для расчёта сходства. Его следует согласовать с доступной памятью и ресурсами GPU.
- Значения `sim_*` — косинусное сходство, а не вероятность принадлежности нарратива к категории.
